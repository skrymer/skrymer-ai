## msw 3 names

- `server.listen({ onUnhandledFrame: 'error' })` is msw 3's name for msw 2's
  `onUnhandledRequest`.
- A custom `onUnhandledFrame` callback's `defaults.error()` only prints. It doesn't fail
  anything. To fail, record the request and throw. In Node, msw answers a throwing callback
  with `500 Unhandled Exception`, so the page meets an error, and the recorded list fails the
  test once it ends (an `afterEach` in Vitest, the fixture's teardown in Playwright).

## Vitest

```ts
// test/mocks/node.ts
import { setupServer } from 'msw/node'
import { handlers } from './handlers'
export const server = setupServer(...handlers)

// test/setup.ts (setupFiles in vitest.config)
beforeAll(() => server.listen({ onUnhandledFrame: 'error' }))
afterEach(() => server.resetHandlers())
afterAll(() => server.close())
```

- The client must send an **absolute** URL for the interceptor to see it. Under jsdom or
  happy-dom, give the client `baseURL: location.origin`, or match handlers with a `*/`
  prefix.
- A read still in flight when the file ends escapes every guard. `afterAll` closes the
  server, so the late request goes to the real network and only logs `ECONNREFUSED` or
  "fetch failed" to stderr while the suite stays green. A test that mounts a page waits for
  what the page's post-mount reads draw before it ends.

## Playwright: the `network` fixture

`@msw/playwright`'s `defineNetworkFixture({ context, handlers, onUnhandledFrame })` routes
every request of the browser context through `context.route`, not a service worker, so no
`mockServiceWorker.js` ships with the app. Extend the suite's `test` with it once
(`e2e/support/network.ts`) and have every mocked spec import that `test`.

- `skipAssetRequests` (on by default) lets JS, CSS and HTML through to the dev server.
- End the handler list with the same terminal fall-through handler as in Vitest, and fail
  the test at the fixture's teardown, listing each request it caught (`GET /api/invoices`).
- `page.route` beats `context.route`, so a spec's own route still wins. That's how a
  third-party route (a CDN abort) keeps working, and why the lint preset refuses a
  `page.route` on the app's API.
- A fixture that has to switch the handlers off for a while calls `network.disable()` and
  re-enables them in a `finally`. msw's `disable()` throws when the handlers are already
  disabled, so the teardown would fail every test otherwise.
- Playwright doesn't resolve the app's path aliases or auto-imports. Import `test/mocks`
  relatively from `e2e/`, and keep handlers free of app-only globals by passing those values
  in.
- The package is pre-1.0 and calls its use of `context.route` an implementation detail.
  Re-check this section on each bump.

## Dev-server mocking

This one is opt-in, behind an env flag (for example `VITE_API_MOCKS=on`). In the client entry,
when the flag is on, start `setupWorker(...handlers)` from `msw/browser` before the app
mounts, with `onUnhandledFrame: 'bypass'`, so only the endpoints that have handlers are
mocked. It's the one runtime that needs the service worker, so run `npx msw init public/`.
Never turn it on in a build that ships.

## Typing

- **OpenAPI:** `createOpenApiHttp<paths>({ baseUrl: '*' })` from `openapi-msw`, with `paths`
  generated by `openapi-typescript`. It checks the path, its params, the query keys, the
  request body, the status and the response body. `response(status).json(body)` exists only
  for a `*/json` media type. If every body comes out `unknown`, the spec declares `*/*`, so
  fix the backend's produced media type instead of casting.
- **A generated client and no spec:** type each resolver's return value with the client's
  response types (`HttpResponse.json<Invoice[]>(…)`).
- **GraphQL:** see [graphql.md](graphql.md).
- Typecheck `test/**`, the folder holding the handlers. A type annotation in a folder the
  typecheck skips checks nothing.

## Nuxt

Under `@nuxt/test-utils` (`environment: 'nuxt'`), stock `setupServer` sees nothing until two
things are dealt with:

1. `@nuxt/test-utils` wraps `fetch`. A relative URL that `registerEndpoint` hasn't registered
   answers 404 without reaching the network. Rebind `$fetch` in `beforeAll` with
   `createFetch({ fetch, defaults: { baseURL: location.origin } })`, so a relative `/api/*`
   becomes absolute and reaches the interceptor. Restore it in `afterAll`.
2. msw's fetch interceptor builds a `Request` from happy-dom's global and hands it to Node's
   `fetch`, which can't read a foreign `Request` ("Failed to parse URL from [object Request]").
   Wrap `fetch` to unwrap a `Request` into its URL and init. Node's `fetch` also refuses
   happy-dom's `AbortSignal`, so race the response against the signal instead of passing it
   on.

Install both in one `installMswServer()` that the setup file calls, and pin each part with a
test of its own. Never use `registerEndpoint`: it bypasses the unhandled check, and the
lint preset refuses it. Nuxt Icon looks up unbundled icons on a CDN, so answer that host with
a 404 handler rather than letting it reach the network.

## Lint preset

The web-e2e pack ships `lint/eslint-msw.mjs`, built from core ESLint rules alone. In test files
it refuses `vi.mock` of an HTTP client or the project's API module, a stubbed or replaced
`fetch`, `registerEndpoint`, and a `page.route` / `context.route` on the app's API, on every
request, or on a pattern it can't read. Until setup installs it, copy the file into the
project and spread it last:

```js
// eslint.config.mjs
import { mswBans } from './eslint/msw-bans.mjs'
export default [...config, ...mswBans({ apiModules: ['~/api/client'], clients: ['@acme/http'] })]
```

A later `no-restricted-syntax` replaces it rather than merging. A project with selectors of its
own adds `...mswRestrictedSyntax(options)` to its own list instead. The ban reads the usual
spellings, not a pattern built to slip past it.

## Traps

- **A `{ once: true }` error override on a GET** shows as a success when the client retries
  (ofetch retries a failed GET by default): the retry reaches the baseline. Override without
  `once`, or have the call pass `retry: 0`.
- **A request that fails and then recovers on Retry** is a failure override with a predicate.
  It returns `undefined` once the predicate is false, and falls through to the handler beneath
  it: `failingRead(path, () => down)`.
- **Holding a request open** is a handler that awaits a gate, and falls through once
  released: `held(method, path)` returning `{ handler, arrived, release }`. Await `arrived`
  to act while the request is in flight. Read the body from a clone, because a handler that
  reads the body and falls through leaves the next one "Body has already been used". A
  request released at the end of a test finishes in the next one, so wait for its effect on
  screen after `release()`.
- **A spec moved off `page.route`** meets reads its old mocks never mentioned, which used to
  fail quietly at the proxy. The unhandled failure names each one. Add them to the baseline.
- **"Not asked again"** is a handler whose later reads answer differently
  (`reads++ === 0 ? full : empty`), so a duplicate read changes the screen. Check at the end,
  where a late read would have landed.
- **"Sends nothing"** is shown by what a send would have made visible, such as the server's
  refusal in its own words. A neighbouring test seldom covers it.
- **A stale re-read** (a superseded load that mustn't land) is `getResponse(handlers,
  request)` inside the holding handler, returned once the hold is released.
- **A value the page sends and never shows** (a time zone, a device id) is held by a guard:
  the factory takes the right value and refuses any other.
- **A derived figure in a mock follows the backend's arithmetic, operation for operation.**
  Seed at least two values where the plausible wrong inputs give different answers, and pick
  inputs that divide exactly rather than loosening to `toBeCloseTo`.
- **Seed only state the backend could hold.** A factory throws on a fixture that describes
  the same thing two ways.
- **A held clock moves the day the page sends.** Under `page.clock.install({ time })` or
  `vi.setSystemTime`, give the handler that day, not the real today.
- **Waiting is not asserting.** `page.waitForResponse` can synchronise a step when nothing
  on screen changes, but it never stands in for proving what was sent.
- **A browser stub replaces only the member a test needs.** Handlers run in the test's
  globals, so a stub of a whole constructor reaches them too.
- **A body is written back in the backend's field order**, since a test that lists fields
  reads that order.
